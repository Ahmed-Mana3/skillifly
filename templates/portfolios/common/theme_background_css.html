{% comment %} Theme colour overrides — emitted only when the profile saved a background and/or accent colour for a theme that supports them (core.theme_colors.THEME_BACKGROUND_SPECS). Requires: theme_background, the dict returned by core.theme_colors.resolve_background_palette, with keys custom (bool) -> no saved background; emit no background tokens accent_custom (bool) -> no saved accent; emit no accent tokens family (str) -> which CSS token vocabulary the theme spells its background with; see core.theme_colors.THEME_BACKGROUND_SPECS accent_tokens (dict) -> slot -> CSS custom properties carrying the accent, e.g. {'primary': ('--accent',), 'glow': ('--accent-glow',)} accent_channels (dict) -> slot -> CSS custom properties carrying that tone as bare RGB channels, e.g. {'primary': ('--accent-rgb',)} accent_channel_vars (list) -> the same thing already resolved against the live palette: [{'property': '--accent-rgb', 'channels': '255, 61, 107'}, ...] palette (dict) -> background, ink, ink_soft, hard_ink, surface, surface_2, surface_glass, text, text_muted, text_faint, border, border_strong, nav, overlay, hero_mid, hero_veil, shadow, texture, hairline, star_empty, fill_ink, fill_ink_soft, fill_wash, fill_empty, text_shadow accent_palette (dict) -> accent/primary, partner, trio, glow, soft, ink, and a _rgb companion for each Why this is one partial for thirteen themes ------------------------------------------ Each theme family names the same ideas differently — minimal says --bg-dark, editorial-studio says --paper, the neo-brutalist themes say --bg but pair it with hard borders and offset shadows, and the animated pair writes its chrome as literals. Rather than fork the stylesheet per theme, this file emits one neutral --sf-* token set and then bridges it into whichever vocabulary `family` names. core/theme_colors.py owns *what* each theme looks like; this file only owns how to say it. The accent is the same story one level down: the registry lists which custom properties carry it, so the loop below needs no per-theme branch. A theme with an empty accent map (the neo-brutalist family, whose accent *is* the hard ink) emits nothing, and the editor does not offer the control in the first place. Custom properties only move a colour the theme spells as a token. Creative fades its own brand colour with rgba(255, 61, 107, .08) in about forty places — hover washes, card glows, pill fills, the ambient orbs — and those literals cannot follow an overridden token. So the registry also lists `accent_channels`, the properties that carry each tone as bare "255, 61, 107" channels, and the theme writes rgba(var(--accent-rgb), .08) instead. Every template that lists channels has to define the matching default in its own :root, so an untouched theme still renders exactly as shipped. Custom properties set in :root win on source order, so this block must stay the last thing in . The handful of rules that paint a literal instead of a token (minimal's body, editorial-studio's gradient body) are handled with !important below. Where a theme paints a literal that is *meant* to stay put — the black letterbox behind a video, the scrim over a thumbnail — it is left alone on purpose: that surface belongs to the media, not to the palette. {% endcomment %} {% if theme_background.custom or theme_background.accent_custom %} {% endif %}
